## Findings

1. **App bug, fixed (`27d2fa2`):** editor transport row overflowed by 4 px on
   360 dp wide phones (`lib/features/beat_editor/presentation/widgets/editor_controls.dart:96`,
   fixed 156 px speed control + 48/64/48 px buttons = 332 px in 328).
   Host regression: `test/features/beat_editor/presentation/editor_narrow_screen_test.dart`.
2. **App bug, fixed (`593ad38`):** a failed or cancelled import left the
   Analyzing screen stuck at 100 % with no error
   (`lib/features/import/presentation/pages/analyzing_screen.dart`, listener):
   the BlocConsumer listener ran `maybePop` before the builder rebuilt the
   PopScope, which still said `canPop: false`, so the pop was refused. Now
   pops after the rebuild. Host regression:
   `test/features/import/presentation/analyzing_screen_test.dart` (real
   AppRouter; failed without the fix).
3. **Known issue, not fixed (lead decision):** Android's AAC decode keeps
   the 2048-sample encoder priming — +46.4 ms at 44.1 kHz, +42.7 ms at
   48 kHz — plus 256–344 padding frames at the end, for M4A and ADTS alike;
   `WavDecoder` ignores `KEY_ENCODER_DELAY`/`KEY_ENCODER_PADDING`. Packs stay
   in sync because song.wav is the master clock (I7 and I10 sync diff 0).
4. Native decode, encode (AAC and H.264), probe, cancel and file copy all
   worked on the device; no Kotlin exception in any flow.
5. The guide video came out 720×1280 rather than 1080×1920 on this phone.
