## Findings

1. **App bug, fixed:** editor transport row overflows by 4 px on 360 dp wide
   phones (`lib/features/beat_editor/presentation/widgets/editor_controls.dart:96`,
   fixed width 156 px speed control). Fix + host regression test `82a2a5d`.
2. **AAC priming is not trimmed on Android.** Every AAC decode (M4A and ADTS)
   starts 2048 samples late (46.4 ms at 44.1 kHz, 42.7 ms at 48 kHz) and ends
   with 256–344 extra padding frames. Within the app this is consistent
   (beats are on `song.wav`'s timebase and both M4A exports carry the same
   shift, sync diff 0), so it doesn't break the CapCut/VN pack. It would
   matter if a user pairs the guide with their *original* M4A, and it means
   `WavDecoder` ignores `MediaFormat.KEY_ENCODER_DELAY` / `KEY_ENCODER_PADDING`
   (files from iTunes etc. carry them). Not fixed: needs a device to verify,
   and a real third-party M4A to see whether the extractor reports a delay.
3. Native decode, encode, probe, cancel and file copy all worked first time
   on the device; no Kotlin crash or error in any flow.
